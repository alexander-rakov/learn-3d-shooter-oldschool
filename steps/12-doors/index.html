Part 3 · Step 12

Doors and push-walls

Wolfenstein's levels are rooms joined by sliding doors, plus the odd secret wall that slides away when you push it. Both break the rule our renderer is built on, that every wall sits on a grid line. A door sits in the middle of its cell; a push-wall moves. One small addition to DDA handles both.

A door is a wall across the middle of a cell

In the map a door is a | (it runs north–south, so you walk through it east–west) or a -. It gets its own cell value, DOOR, and its state lives in a separate list: how far open it is, and what it's doing.

When DDA steps into a door cell, it doesn't stop at the grid line it just crossed. Instead it asks where the ray crosses the line through the middle of the cell. For a | door that's the line x = mapX + 0.5:

t = (mapX + 0.5 − posX) / rayDirX     along = posY + t · rayDirY − mapY

along is how far along the door the crossing is, from 0 to 1. If it's outside that range, the ray leaves through the side of the cell before reaching the middle: it's heading into the wall beside the door.

function crossInCell(vertical, line, mapX, mapY, posX, posY, rayDirX, rayDirY) {
  const t = vertical ? (line - posX) / rayDirX : (line - posY) / rayDirY;
  if (!(t > 0)) return null;                    // behind us (or parallel: NaN)
  const along = vertical ? posY + t * rayDirY - mapY : posX + t * rayDirX - mapX;
  return along >= 0 && along < 1 ? { t, along } : null;
}

This is the same intersection DDA does all the time, just with a line half a cell further in. And because the ray is still d + c·p, t is still depth. The fisheye fix, the wall height and the sprites' depth buffer all work unchanged.

Why the middle, and not the edge of the cell? A door flush with the wall would look like a painted rectangle. Set back half a cell, it sits in a recess with visible sides, and that's what makes it read as a doorway.

Door frames

The sides of that recess are the walls next to the door cell. They'd normally show bricks, but a doorway looks much better with a metal frame there. Spotting them is easy: if the cell DDA was in just before hitting a wall is a door cell, the wall is a door frame. castRay keeps the previous cell's value and reports doorFrame: prev === DOOR.

Sliding open

Each door has an open value from 0 (shut) to 1 (fully open). The panel slides sideways into the wall, so it covers along from open to 1. A ray that crosses the middle line at a smaller along goes through the gap, and DDA carries on into the room beyond.

if (cell === DOOR) {
  const door = map.doors.get(mapY * map.w + mapX);
  const line = door.vertical ? mapX + 0.5 : mapY + 0.5;
  const c = crossInCell(door.vertical, line, mapX, mapY, posX, posY, rayDirX, rayDirY);
  if (c && c.along >= door.open) {
    return { t: c.t, side: door.vertical ? 0 : 1, door, wallX: c.along - door.open, … };
  }
  continue;   // through the gap, or out the side towards a door frame
}

The texture coordinate is along − open, not along, so the texture moves with the panel instead of the panel sliding over a fixed picture.

A door is a small state machine. Press E facing it and it starts opening. Once fully open it waits 4.3 seconds, then starts closing, unless something is standing in the doorway, in which case it opens again. For movement, a door cell is solid unless the door is fully open.

if (d.state === 'opening') {
  d.open = Math.min(1, d.open + dt / DOOR_OPEN_TIME);
  if (d.open === 1) { d.state = 'open'; d.timer = DOOR_STAY_OPEN; }
} else if (d.state === 'open') {
  d.timer -= dt;
  if (d.timer <= 0) d.state = 'closing';
} else if (d.state === 'closing') {
  if (isOccupied(d.x, d.y)) { d.state = 'opening'; continue; }   // something's in the way
  d.open = Math.max(0, d.open - dt / DOOR_OPEN_TIME);
  if (d.open === 0) d.state = 'closed';
}

“Using” is deliberately simple, as in Wolfenstein: take the direction you face, round it to north, east, south or west, and act on the cell right next to yours in that direction. No ray needed, and it works on open doors too (using an open door closes it).

Push-walls

A push-wall is a secret: it looks exactly like the walls around it (in the map it's a lowercase a–c instead of 1–3). Use it and it slides two cells away from you, opening a passage.

While it moves, its front face is a line offset of the way into its cell, so the renderer needs exactly the door test with a different line: x = mapX + offset for a wall moving east. The cell ahead, which the block is sliding into, is marked as an ordinary wall in the meantime. When offset reaches 1 the block has moved a whole cell: the cell behind it becomes floor, and it continues from the next one.

We only ever draw the block's front face. That works because a secret passage is exactly one cell wide: the block's sides slide along the passage walls, so you can never see them. Only one push-wall can move at a time, which keeps the bookkeeping to a single object.

  • Stand in a doorway and wait. The door won't close while you're in it.
  • Look through a half-open door in slow motion. One column hits the panel at the door's depth, the next one goes through the gap and hits a wall far away. Sprites in the next room show only through the gap, because the depth buffer now holds the door's depth.
  • Turn off the door-frame texture: the doorway turns into a hole in a brick wall.
  • There is a secret in the small blue room on the left (through the door in the south wall of the room you start in). Look for a wall that isn't what it seems, and press E.

Door tiles, half-steps and pwallpos

In Wolfenstein's tile map, a door tile has its top bit set (0x80), and the other bits say which door it is. Each door has a state (dr_open, dr_closed, dr_opening, dr_closing) and a position in doorposition[], a 16-bit number from 0 (shut) to 0xFFFF (open).

When the ray-casting loop in AsmRefresh runs into a door tile, it adds half of its usual step to reach the middle of the tile, checks that the intercept is still inside the tile, and compares it with the door's position to decide between door and gap. That's our crossInCell, in fixed point. The door then waits OPENTICS, 300 tics of the 70 Hz clock (about 4.3 seconds), before it tries to close. Walls next to a door are drawn with a dedicated door-side texture.

Push-walls work the same way. There's only ever one moving push-wall, kept in a handful of global variables (pwallstate, pwallx, pwally, pwalldir, pwallpos), and the renderer offsets its intercept by pwallpos just as we use offset. It slides two tiles and stops, or stops earlier if something is in the way.

Doors also mattered for gameplay beyond movement. A closed door separates two areas of the level, and sound doesn't pass through it. That's how enemies decide whether they heard your gunshot, which is the next step.
