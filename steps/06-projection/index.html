Part 2 · Step 6

Perspective projection: from distance to wall height

We can find where each ray hits a wall. Turning that into a picture needs one more idea: things that are further away look smaller, in exact proportion to their distance. That's one division per column, and it gives us our first 3D frame.

Similar triangles

Look at the world from the side. The eye is at height 0.5 (half a wall; Wolfenstein's walls are one cell high and the eye is in the middle), and the projection plane, our screen, is one unit in front of it. A wall of height 1 stands at distance z.

Draw lines from the eye to the top and bottom of the wall. Where they pierce the plane is where the wall appears on screen. The small triangle (eye → plane) and the big one (eye → wall) have the same angles, so their sides are in proportion:

height on plane / 1 = wall height / z    ⇒    height on plane = 1 / z

From plane units to pixels

Now convert “units on the plane” to pixels. In step 3 we said the plane's half-width is |p| = tan(FOV/2) and that it spans half the screen, W/2 pixels. So one unit on the plane is

projScale = (W/2) / |p|  pixels

Using the same scale vertically keeps pixels square. With W = 320 and a 66° FOV, projScale ≈ 246: a wall one unit away is 246 pixels tall, which is taller than our 200-pixel screen, as it should be when you stand that close. The whole projection is:

lineHeight = projScale / z

The wall column is centred on the horizon (screen row H/2, because the eye is at mid-wall height). Everything above it is ceiling, everything below is floor.

Our first frame

Put it all together. For every column: build the ray (step 3), cast it (step 5), turn the distance into a height, and fill one vertical strip of pixels.

for (let x = 0; x < w; x++) {
  const c = 2 * x / w - 1;
  const rayDirX = p.dirX + p.planeX * c;
  const rayDirY = p.dirY + p.planeY * c;
  const hit = castRay(map, p.x, p.y, rayDirX, rayDirY);

  const dist = hit.t * Math.hypot(rayDirX, rayDirY);    // Euclidean distance
  const lineHeight = projScale / dist;
  const top    = Math.max(0, Math.floor(h / 2 - lineHeight / 2));
  const bottom = Math.min(h, Math.floor(h / 2 + lineHeight / 2));

  let color = WALL_COLORS[hit.cell];
  if (hit.side === 1) color = shade(color);   // darker on N/S faces

  for (let y = 0; y < top; y++)       pixels[y * w + x] = CEILING_COLOR;
  for (let y = top; y < bottom; y++)  pixels[y * w + x] = color;
  for (let y = bottom; y < h; y++)    pixels[y * w + x] = FLOOR_COLOR;
}

Two details:

  • Side shading. Faces hit through a horizontal grid line (side = 1) get half brightness. Without lighting, all walls would be the same flat colour and corners would vanish. This one trick gives the classic look.
  • Pixels, not drawing commands. We render into a Uint32Array that shares memory with an ImageData (one 32-bit integer per pixel), then copy it to a 320 × 200 canvas that CSS scales up with image-rendering: pixelated. Every pixel is ours, just like writing to VGA memory.

Something's not right. Walk up to a long straight wall and turn left and right. It bulges: the middle looks closer than the ends, as if seen through a fisheye lens. The distance we used, the straight-line Euclidean one, seems like the obviously correct choice, so why is it wrong? That's the next step.

VGA mode 13h, and compiled scalers

Wolfenstein ran in VGA's 320 × 200, 256-colour mode. In the simple version of that mode (“mode 13h”) the screen is just 64,000 bytes of memory starting at address A000:0000, one byte per pixel, which is a palette index. Wolfenstein actually used an “unchained” variant (often called Mode X style), which splits memory into four planes. That's awkward for drawing single pixels, but it allows double buffering: draw the next frame off-screen, then flip.

The wall columns were drawn by compiled scalers. At startup the game generated machine code, one routine for every possible column height. Each routine is a fully unrolled list of “copy texel i to row j” instructions, with no loop, no counter, and no fractional stepping. Drawing a column meant jumping into the routine for its height. That's self-modifying-code-era performance tuning, and it took a noticeable chunk of the 640 KB of memory.

The ceiling and floor were never “drawn” at all: Wolfenstein clears the view to two solid colours each frame, like our version here. (Ceiling colours vary per level; the floor is always the same dark grey.)
