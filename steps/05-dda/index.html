Part 1 · Step 5

DDA: walking a ray through the grid, one cell at a time

This is the core of every Wolfenstein-style engine. Instead of tiny steps, we jump straight from one grid line crossing to the next, so we visit exactly the cells the ray passes through and find the exact hit point.

Crossings come at regular intervals

Take the ray P(t) = pos + t·r, where r = (rx, ry) is the ray direction (it doesn't need to be a unit vector). Look only at the x coordinate: it changes by rx per unit of t. The vertical grid lines x = 0, 1, 2, … are one unit apart, so the ray crosses one every

Δtx = 1 / |rx|     and likewise     Δty = 1 / |ry|

The crossings of vertical lines are evenly spaced along the ray, and so are the crossings of horizontal lines. Only the first one of each is special, because the eye sits somewhere inside a cell. If the ray goes right (rx > 0), the first vertical line is at x = mapX + 1, which takes (mapX + 1 − posx) · Δtx to reach. If it goes left, the line is at x = mapX, which takes (posx − mapX) · Δtx.

The algorithm

Keep two numbers: sideDistX, the t at which we'll cross the next vertical line, and sideDistY, the same for the next horizontal line. Then repeat:

  1. Whichever is smaller comes first. Say it's sideDistX: we cross a vertical line and move one cell left or right (mapX += stepX).
  2. The next vertical line is Δtx further: sideDistX += deltaDistX.
  3. Check the new cell. If it's a wall, stop. The current t is the exact distance to the wall face, and we know which kind of face we hit: a vertical line means an east/west-facing wall (side = 0), a horizontal line means north/south (side = 1).

Here it is, straight from this step's raycaster.js (minus the trace recording):

function castRay(map, posX, posY, rayDirX, rayDirY) {
  let mapX = Math.floor(posX);
  let mapY = Math.floor(posY);

  const deltaDistX = rayDirX === 0 ? 1e30 : Math.abs(1 / rayDirX);
  const deltaDistY = rayDirY === 0 ? 1e30 : Math.abs(1 / rayDirY);

  let stepX, stepY, sideDistX, sideDistY;
  if (rayDirX < 0) { stepX = -1; sideDistX = (posX - mapX) * deltaDistX; }
  else             { stepX =  1; sideDistX = (mapX + 1 - posX) * deltaDistX; }
  if (rayDirY < 0) { stepY = -1; sideDistY = (posY - mapY) * deltaDistY; }
  else             { stepY =  1; sideDistY = (mapY + 1 - posY) * deltaDistY; }

  let t = 0, side = 0, cell = 0;
  for (let i = 0; i < MAX_STEPS; i++) {
    if (sideDistX < sideDistY) {
      t = sideDistX; sideDistX += deltaDistX; mapX += stepX; side = 0;
    } else {
      t = sideDistY; sideDistY += deltaDistY; mapY += stepY; side = 1;
    }
    cell = mapCell(map, mapX, mapY);   // outside the map counts as wall
    if (cell !== 0) break;
  }
  return { t, mapX, mapY, side, cell };
}

Notice what's not in the loop: no multiplication, no division, no square root. Just a comparison, an addition and an increment. Divisions happen once per ray, outside it. A wall 10 cells away now costs around 15 iterations instead of 1,000, and the answer is exact.

  • Aim almost exactly horizontally. deltaDistY becomes huge: the ray hardly ever crosses a horizontal line, so it's almost all orange steps.
  • Aim at 45°: deltaDistX = deltaDistY, and the steps alternate.
  • Find the corner case from step 4 (a ray grazing a wall corner). DDA never misses it.

What “t” means here (and a preview)

We return t, not a Euclidean distance. The hit point is pos + t·rayDir, so the real distance is t · |rayDir|. In the demo rayDir has length 1, so the two are the same. In the real engine they won't be: rayDir = d + c·p from step 3 is longer than 1 towards the screen edges. In step 7 that turns out to be exactly what we want.

Why it's called DDA, and what Wolf3D actually did

“Digital Differential Analyzer” is an old name from line-drawing hardware: step along one axis, accumulate the other in increments. The grid version, “visit every cell a ray touches, in order”, was written up for 3D voxel grids by Amanatides and Woo in 1987 (A Fast Voxel Traversal Algorithm for Ray Tracing), and it's the same thing we just wrote in 2D.

Wolfenstein's ray caster (an assembly routine called AsmRefresh) is organised a little differently but rests on the same idea. It tracks the next x-intercept and y-intercept in fixed point, steps them by the tangent of the ray angle (from a table, of course), and always advances whichever is nearer. Everything is integer adds and compares.

It also cheats in a useful way: because walls fill whole cells and every ray stops at the first one, it never needs to consider anything behind a wall. That's why Wolfenstein has no overdraw for walls: each screen column is drawn exactly once.
